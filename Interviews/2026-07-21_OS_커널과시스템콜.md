## 개념: 커널과 시스템 콜

### Q1. 커널의 정의와 역할
- **내 답변 요약**: 커널은 PC가 실행된 순간부터 종료될 때까지 실행되는 프로그램이며, 사용자가 직접 접근하면 안 되는 영역의 처리를 담당한다고 설명했다.
- **평가**: 특권 영역과 보호가 필요하다는 방향은 맞았다. 다만 커널이 CPU에서 항상 명령을 실행한다기보다 메모리에 상주하며 필요할 때 실행된다고 표현하는 편이 정확하다. 하드웨어·CPU·메모리·프로세스·파일·장치를 관리하고 사용자 프로그램에 추상화된 서비스를 제공한다는 역할을 보강해야 한다.

### Q2. 시스템 콜과 CPU 실행 모드
- **내 답변 요약**: x86 링 구조에서 Ring 0이 커널 모드이며, 사용자 프로그램이 하드웨어 관련 기능을 사용하기 위해 시스템 콜을 통해 커널에 요청한다고 설명했다.
- **평가**: 시스템 콜과 특권 수준 전환의 핵심은 정확했다. 시스템 콜은 사용자 프로그램이 커널 서비스를 요청하는 통제된 인터페이스이며, 직접 하드웨어와 통신하는 동작 자체는 아니다.

### Q3. 시스템 콜 진입부터 사용자 코드 복귀까지
- **내 답변 요약**: 시스템 콜 전에 프로그램 카운터와 레지스터 값을 저장하고 커널 모드로 진입해 작업한 뒤 돌아온다고 설명했으며, 처음에는 이 과정을 컨텍스트 스위칭이라고 표현했다.
- **평가**: 실행 문맥 보존과 모드 전환은 짚었지만, 모드 전환과 컨텍스트 스위칭을 처음에 혼동했다. 시스템 콜이 즉시 끝나 같은 스레드로 복귀하면 모드 전환만 발생하며, 블로킹 등으로 스케줄러가 다른 스레드를 선택할 때 별도의 컨텍스트 스위칭이 발생한다.

### Q4. 같은 스레드에서의 시스템 콜과 컨텍스트 스위칭
- **내 답변 요약**: 같은 스레드가 계속 실행된다면 반드시 컨텍스트 스위칭이라고 할 수 없다고 정정했다.
- **평가**: 재질문 후 두 개념의 구분을 정확히 회복했다.

### Q5. 사용자 복귀 문맥의 저장 위치
- **내 답변 요약**: 처음에는 TCB에 저장될 것이라고 추측했고, 힌트 후에도 사용자 스레드의 사용자 스택에 저장된다고 답했다.
- **평가**: 🔴 핵심 약점. 사용자 스택은 사용자 프로그램이 수정할 수 있으므로 특권 전환 시 신뢰할 수 있는 저장 위치가 아니다. 일반적으로 사용자 PC·SP·플래그·레지스터 등의 복귀 문맥은 해당 스레드의 커널 스택에 trap frame 형태로 보존된다. TCB가 커널 스택이나 스케줄링 문맥을 참조할 수는 있지만 즉시 저장되는 trap 문맥과 구분해야 한다.

## 모범답안

커널은 운영체제의 특권 핵심부로서 CPU·메모리·프로세스·파일·장치 등의 자원을 관리하고, 사용자 프로그램에 보호된 추상화와 서비스를 제공한다. 메모리에 상주하지만 CPU에서 항상 실행되는 것은 아니며 시스템 콜·예외·인터럽트 등을 처리할 때 실행된다.

사용자 프로그램은 시스템 콜 번호와 인자를 준비하고 `syscall` 또는 trap 명령을 실행한다. CPU는 사용자 모드에서 커널 모드로 특권 수준을 변경하고 커널 진입점으로 이동한다. 커널은 사용자 복귀 문맥을 해당 스레드의 커널 스택에 trap frame 형태로 보존하고, 시스템 콜 번호·인자·포인터·권한을 검증한 뒤 요청을 처리한다.

요청이 즉시 끝나면 저장한 문맥을 복원하고 return-from-trap 명령으로 같은 스레드의 사용자 모드 코드에 복귀한다. 이때는 모드 전환만 일어나며 반드시 컨텍스트 스위칭이 발생하는 것은 아니다. 시스템 콜이 I/O 대기 등으로 블로킹되면 스케줄러가 다른 스레드를 선택할 수 있고, 이때 별도의 컨텍스트 스위칭이 발생한다.

## 약점·복습포인트

- 커널은 메모리에 상주하지만 CPU에서 항상 실행되는 것은 아니라는 구분
- 시스템 콜에 따른 모드 전환과 스레드 교체에 따른 컨텍스트 스위칭의 구분
- 사용자 복귀 문맥은 사용자 스택이 아니라 스레드별 커널 스택의 trap frame에 보존
- TCB의 스케줄링 문맥과 시스템 콜 진입 시 trap frame의 역할 구분
- 시스템 콜 진입 시 인자·사용자 포인터·권한 검증 단계

## Q1. NAT의 정의와 사용 목적
- **내 답변 요약**: NAT는 Network Address Translation의 약자로 IP 주소를 변환하며, 사설 IP와 공인 IP를 변환할 때 사용한다고 설명했다.
- **평가**: 주소 변환과 사설·공인 IP 연결이라는 핵심은 맞았다. 다만 대표적인 사용 목적인 IPv4 공인 주소 부족 완화와 여러 사설 호스트의 공인 IP 공유가 빠졌다.

## Q2. NAT 장비의 패킷 변환과 상태 관리
- **내 답변 요약**: 내부 호스트가 외부 서버로 보낸 패킷의 출발지 IP를 NAT가 변경하고, 응답을 원래 호스트로 돌려보내기 위해 변환 전후 정보를 NAT 테이블에 기록한다고 설명했다.
- **평가**: 전체 흐름은 정확했다. 실제 NAT 테이블은 주소뿐 아니라 프로토콜과 포트를 포함한 변환 매핑 및 연결 상태를 관리한다.

## Q3. 여러 내부 호스트가 하나의 공인 IP를 공유하는 방법
- **내 답변 요약**: 연결은 출발지·목적지 IP와 포트로 식별되고, NAT가 내부 호스트마다 서로 다른 포트 번호를 매핑하여 구분한다고 설명했다.
- **평가**: NAPT·PAT의 원리를 이해하고 있었다. 다만 처음에는 구체적인 변환 결과를 제시하지 않아 답변이 추상적이었다.

```text
TCP 10.0.0.2:50000 ↔ 198.51.100.7:61001
TCP 10.0.0.3:50000 ↔ 198.51.100.7:61002
```

두 내부 연결의 원래 출발지 포트가 같더라도 NAT가 외부 포트를 다르게 할당할 수 있다. 외부에서 온 응답의 목적지 공인 IP·포트와 프로토콜을 NAT 테이블에서 조회해 원래 내부 IP·포트로 역변환한다.

## Q4. 외부에서 먼저 시작하는 연결과 포트 포워딩
- **내 답변 요약**: 외부 호스트는 NAT의 공인 IP와 포트만 알 수 있고 기존 NAT 매핑이 없으므로 내부의 어느 호스트로 전달해야 하는지 결정할 수 없다고 답했다. 포트 포워딩이나 고정 매핑으로 해결할 수 있다고 설명했다.
- **평가**: 원인과 해결 방법을 모두 정확하게 설명했다.

## Q5. NAT와 체크섬 갱신
- **내 답변 요약**: IP 주소와 포트 번호를 바꾸면 이를 사용하는 체크섬도 함께 변경해야 한다고 답했다.
- **평가**: 필드 변경이 체크섬 갱신을 요구한다는 점은 알고 있었다. 하지만 IPv4 헤더 체크섬과 TCP·UDP 체크섬의 위치와 보호 범위를 명확히 구분하지 못했다.

## Q6. IPv4·TCP·UDP 체크섬의 범위
- **내 답변 요약**: 힌트 후 IPv4 체크섬은 패킷 전체가 아니라 헤더만 검사할 것이라고 추론했다. TCP·UDP 체크섬에 포함되는 IP 계층 값은 답하지 못했다.
- **평가**: IPv4 헤더 체크섬의 범위는 맞혔다. TCP·UDP 체크섬이 전송 계층 헤더와 데이터뿐 아니라 IP 출발지·목적지 주소 등을 담은 의사 헤더까지 사용한다는 점이 약점으로 확인됐다.

## 핵심 정리

### NAT와 NAPT·PAT

NAT는 패킷이 NAT 장비를 통과할 때 IP 주소를 변환하는 기능이다. 가정이나 사무실에서 흔히 사용하는 방식은 주소와 포트를 함께 변환하는 NAPT 또는 PAT다. 여러 사설 호스트가 하나의 공인 IPv4 주소를 공유할 수 있어 IPv4 주소 부족을 완화한다.

NAT 장비는 변환 매핑을 상태로 저장한다.

```text
프로토콜 + 내부 IP:포트 ↔ 공인 IP:변환 포트
```

응답 패킷이 도착하면 공인 IP·목적지 포트와 프로토콜을 바탕으로 NAT 테이블을 조회하여 원래 내부 주소로 역변환한다.

### 외부에서 먼저 시작하는 연결

내부에서 시작된 통신은 NAT가 동적으로 매핑을 생성한다. 반면 외부에서 먼저 도착한 패킷은 기존 매핑이 없으므로 어느 내부 호스트로 전달할지 알 수 없다. 외부 연결을 허용하려면 공인 IP의 특정 포트를 내부 IP·포트에 연결하는 포트 포워딩 같은 정적 매핑을 설정할 수 있다.

### 체크섬 갱신

- **IPv4 헤더 체크섬**: IPv4 헤더만 보호한다. NAT가 출발지 또는 목적지 IP를 바꾸면 갱신해야 한다.
- **TCP 체크섬**: TCP 헤더와 데이터 및 IP 의사 헤더를 사용한다.
- **UDP 체크섬**: UDP 헤더와 데이터 및 IP 의사 헤더를 사용한다.

TCP·UDP 의사 헤더에는 출발지 IP, 목적지 IP, 상위 프로토콜 번호, 전송 계층 길이 등이 포함된다. TCP·UDP 포트는 각각의 전송 계층 헤더 안에 있다. 따라서 NAT가 IP 주소나 포트를 변경하면 해당 전송 계층 체크섬도 갱신해야 한다.

## 음성 답변의 사고 흐름·구성 평가

### 잘한 점
- NAT의 주소 변환, 상태 추적, 응답 역변환을 자연스러운 순서로 연결했다.
- 외부에서 시작한 연결이 실패하는 이유를 “NAT 테이블에 매핑이 없다”는 핵심으로 바로 좁혔다.
- 구체적인 용어가 즉시 떠오르지 않아도 포트를 다르게 매핑한다는 원리를 추론했다.

### 개선할 점
- 포트 변환 질문에서 같은 원리를 반복했지만 요청받은 변환 전후의 숫자 예시를 바로 제시하지 않아 답변이 맴돌았다.
- `원리 → 구체적인 매핑 예시 → 응답 역변환` 순서로 답하면 전달력이 좋아진다.
- 체크섬 설명에서 IP 헤더와 TCP·UDP 헤더의 필드가 섞였다. 먼저 각 체크섬의 위치와 보호 범위를 분리해 설명해야 한다.
- 명백한 받아쓰기 변환 오류는 지식 오류로 평가하지 않았으며 속도·억양·발음은 평가 대상이 아니다.

## 모범답안 요점

NAT는 패킷의 IP 주소를 변환하는 기능이며, NAPT·PAT는 포트까지 변환해 여러 사설 호스트가 하나의 공인 IPv4 주소를 공유하도록 한다. NAT 테이블은 프로토콜과 내부·외부 IP 및 포트의 매핑을 저장하고 응답을 원래 내부 연결로 역변환한다.

외부에서 먼저 들어온 패킷에는 동적 매핑이 없으므로 일반적으로 내부 호스트로 전달되지 않는다. 필요하면 포트 포워딩으로 정적 매핑을 설정한다.

NAT가 주소나 포트를 변경하면 IPv4 헤더 체크섬과 TCP·UDP 체크섬도 알맞게 갱신해야 한다. IPv4 체크섬은 IPv4 헤더만 보호하며, TCP·UDP 체크섬은 전송 계층 헤더와 데이터 및 IP 주소 등이 포함된 의사 헤더를 사용한다.

## Q1. DHCP의 정의와 역할
- **내 답변 요약**: 공유기 등이 내부 네트워크의 호스트마다 사설 IP를 동적으로 배정하는 과정이라고 설명했다. 하나의 공인 IP로 외부와 통신하고 내부에는 사설 IP를 할당하여 IP 주소 부족을 해결한다고 덧붙였다.
- **평가**: 호스트에 IP 주소를 동적으로 할당하고 관리한다는 핵심은 맞았다. 다만 DHCP를 공유기·사설 IP·공인 IP 공유와 강하게 연결하면서 NAT의 역할과 일부 혼동했다. DHCP의 본질은 IP 주소를 포함한 네트워크 설정의 자동 구성이지 IPv4 주소 부족의 직접적인 해결이 아니다.

## Q2. DHCP가 제공하는 설정
- **내 답변 요약**: DHCP가 반드시 사설 IP만 할당하는 것은 아니며, IP 주소 외에 DNS 서버 주소도 제공할 수 있을 것이라고 추론했다.
- **평가**: 두 판단 모두 맞았다. 서브넷 마스크·prefix, 기본 게이트웨이, 임대 시간 등 주요 설정은 답하지 못했다.

## Q3. 초기 주소 할당 과정
- **내 답변 요약**: 아직 IP가 없는 클라이언트가 브로드캐스트를 보내고, DHCP 서버가 사용되지 않은 IP를 골라 제안한다고 설명했다.
- **평가**: 서버 발견과 주소 제안이라는 초기 흐름은 알고 있었다. 그 이후의 요청과 최종 승인 및 네 메시지의 이름은 기억하지 못했다.

## Q4. 여러 DHCP 서버의 제안과 DORA
- **내 답변 요약**: 여러 서버의 제안 중 하나를 선택한 클라이언트가 그 주소를 사용하겠다는 요청을 다시 보내야 한다고 추론했다. 세 번째 메시지를 브로드캐스트하는 이유는 서버의 주소가 아직 특정되지 않은 단계이기 때문이라고 생각했다. `DORA` 힌트 후에도 정확한 메시지 이름은 답하지 못했다.
- **평가**: `발견 → 제안 → 선택 → 확정`이라는 논리적 순서는 복원했다. 그러나 DHCP Request에는 선택한 서버 식별자가 포함된다. 브로드캐스트하는 주요 이유는 선택된 서버와 선택되지 않은 서버 모두에게 선택 결과를 알리고, 아직 설정이 완전히 끝나지 않은 클라이언트가 통신하기 위해서다.

## 핵심 정리

### DHCP의 역할

DHCP(Dynamic Host Configuration Protocol)는 클라이언트에게 IP 주소와 네트워크 설정을 자동으로 제공하는 프로토콜이다. 일반 가정에서는 공유기가 DHCP 서버와 NAT 장비를 모두 겸하는 경우가 많지만 두 기능은 별개다.

DHCP가 제공할 수 있는 대표적인 정보는 다음과 같다.

- IP 주소
- 서브넷 마스크 또는 prefix
- 기본 게이트웨이
- DNS 서버 주소
- 임대 시간
- 도메인 검색 정보 등

### DORA

초기 DHCP 주소 할당은 다음 네 단계로 이루어진다.

1. **DHCP Discover**
   - 클라이언트가 사용 가능한 DHCP 서버를 찾기 위해 브로드캐스트한다.
2. **DHCP Offer**
   - 서버가 사용 가능한 IP 주소와 임대 조건을 제안한다.
3. **DHCP Request**
   - 클라이언트가 선택한 주소와 서버를 알리며 할당을 요청한다.
   - 일반적으로 브로드캐스트하여 선택된 서버와 선택되지 않은 서버 모두에게 선택 결과를 알린다.
4. **DHCP Acknowledgment(ACK)**
   - 선택된 서버가 임대를 최종 승인하고 네트워크 설정을 전달한다.
   - 승인할 수 없으면 DHCP NAK를 보낼 수 있다.

```text
Client                     DHCP Server
  |---- DHCP Discover --------->|
  |<----- DHCP Offer -----------|
  |---- DHCP Request ---------->|
  |<----- DHCP ACK -------------|
```

DHCP는 UDP를 사용하며 서버는 일반적으로 67번, 클라이언트는 68번 포트를 사용한다. 초기 클라이언트는 아직 사용할 IP와 서버 주소를 모를 수 있으므로 브로드캐스트가 필요하다.

### 임대와 갱신

DHCP 주소는 영구 소유가 아니라 일정 시간 동안 임대된다. 일반적으로 임대 시간의 절반인 T1 시점에 기존 서버로 갱신을 시도하고, 갱신하지 못하면 T2 시점에 다른 DHCP 서버에도 브로드캐스트하여 재바인딩을 시도한다. 임대가 만료될 때까지 갱신하지 못하면 해당 주소 사용을 중단해야 한다.

### DHCP Relay

DHCP 브로드캐스트는 일반적으로 라우터를 넘어가지 않는다. 클라이언트와 DHCP 서버가 다른 서브넷에 있다면 라우터나 계층 3 장비의 DHCP Relay Agent가 요청을 중계하고, 서버가 어느 서브넷에 주소를 할당해야 하는지 판단할 정보를 전달한다.

## 음성 답변의 사고 흐름·구성 평가

### 잘한 점
- 정확한 메시지 이름을 기억하지 못해도 `발견 → 제안 → 선택 → 확정` 흐름을 논리적으로 복원했다.
- 모르는 내용과 추론한 내용을 구분하여 표현했다.
- 여러 서버가 제안하면 클라이언트가 하나를 선택해 다시 요청해야 한다는 점을 도출했다.

### 개선할 점
- 첫 답변에서 DHCP의 정의에 NAT와 IPv4 주소 부족 문제까지 포함하면서 개념의 중심이 흐려졌다.
- 공유기가 DHCP와 NAT를 모두 수행할 수 있다는 사실과 두 기능 자체가 동일하다는 설명을 분리해야 한다.
- DHCP Request가 선택한 서버를 식별하면서도 브로드캐스트되는 이유를 정확히 설명해야 한다.
- DORA 메시지 이름과 각 단계의 목적을 면접 답변 수준으로 암기해야 한다.
- 명백한 `DHCP`·`DNS` 받아쓰기 변환 오류는 지식 오류로 평가하지 않았으며 속도·억양·발음은 평가 대상이 아니다.

## 모범답안 요점

DHCP는 클라이언트에게 IP 주소, 서브넷 마스크, 기본 게이트웨이, DNS 서버, 임대 시간 등의 네트워크 설정을 자동으로 제공하는 프로토콜이다. 주소가 없는 클라이언트는 DHCP Discover를 브로드캐스트하고, 서버는 DHCP Offer로 주소를 제안한다. 클라이언트는 DHCP Request로 선택한 제안을 알리고, 서버는 DHCP ACK로 임대를 확정한다.

DHCP는 UDP 67·68번 포트를 사용한다. DHCP 브로드캐스트가 다른 서브넷의 서버에 도달해야 한다면 DHCP Relay Agent가 중계한다. DHCP는 설정 자동화 기능이며 NAT나 공인 IPv4 주소 공유와는 별개의 기능이다.

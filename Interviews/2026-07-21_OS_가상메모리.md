## Q1. 가상 메모리의 정의와 이점
- **내 답변 요약**: 실제 메모리를 추상화해 각 프로세스가 고유하고 연속된 메모리 영역을 가진 것처럼 동작하게 한다고 정의했다. 격리, 논리 주소 사용의 편의성, 비연속 물리 공간 활용을 설명했다.
- **평가**: 핵심은 정확했다. 재배치, 공유 페이지, demand paging, 물리 메모리보다 큰 주소 공간을 보완할 수 있다.

## Q2. VPN·offset·PTE·TLB 주소 변환
- **내 답변 요약**: TLB를 먼저 확인하고 miss이면 페이지 테이블을 거쳐 MMU가 물리 주소를 찾는다고 설명했다. 처음에는 페이지 테이블과 VPN·offset을 혼동했지만 힌트 후 페이지→프레임 매핑과 offset 유지를 회복했다.
- **평가**: 주소 변환의 큰 흐름은 알고 있었다. 가상 주소가 VPN+offset으로 나뉘고, PTE에 PFN·present·권한·accessed·dirty가 들어간다는 점을 복습해야 한다.

## Q3. 페이지 폴트와 페이지 교체
- **내 답변 요약**: 페이지가 RAM에 없으면 디스크에서 가져오고 빈 프레임이 없으면 교체한 후 PTE를 갱신한다고 설명했다. 처음에는 시스템 콜로 요청한다고 답했지만 재질문 후 동기 예외임을 회복했다.
- **평가**: 페이지 폴트는 CPU가 주소 변환 중 발생시키는 동기 예외다. 커널은 매핑·권한을 검사하고 backing data를 프레임에 적재한 뒤 PTE·TLB를 갱신하고 명령을 재실행한다.

## Q4. Dirty page·PTE·TLB shootdown
- **내 답변 요약**: dirty page는 RAM에서 수정돼 디스크와 동기화되지 않은 상태라 write-back이 필요하고, clean page는 재구성 가능하면 버릴 수 있다고 설명했다. PTE 유효 상태와 새 PFN을 갱신하고 stale TLB를 무효화해야 함을 추론했다.
- **평가**: dirty·clean의 차이와 매핑 갱신은 잘 회복했다. 전체 flush는 항상 필요하지 않으며 해당 엔트리만 무효화할 수 있다. 다중 코어에서는 IPI를 이용한 TLB shootdown이 필요할 수 있다.

## Q5. FIFO·LRU·Clock·Belady’s Anomaly
- **내 답변 요약**: FIFO와 LRU의 기본 선택 기준을 알고 있었다. Clock의 reference bit를 처음에 반대로 설명했지만, 힌트 후 1이면 0으로 지우고 넘기며 0이면 교체한다고 정정했다. 프레임을 늘려도 폴트가 증가할 수 있는 현상의 명칭은 기억하지 못했지만 부분집합 속성과 연결했다.
- **평가**: Clock은 하드웨어 reference bit로 최근 사용을 근사한다. FIFO는 stack property가 없어 Belady’s Anomaly가 가능하고 LRU는 stack algorithm이라 발생하지 않는다.

## Q6. Thrashing·Working Set·PFF
- **내 답변 요약**: 다중 프로그래밍 정도가 높아져 Working Set의 합이 전체 프레임보다 커지면 페이지 폴트가 급증한다고 설명했다. PFF를 프레임을 두 배·절반으로 조정하는 전략으로 기억했다.
- **평가**: 스래싱과 Working Set의 원인은 잘 설명했다. PFF 상한 초과 시 프레임을 추가하거나 프로세스를 중단하고, 하한 미만이면 여유 프레임을 회수한다. 전체 수요가 크면 다중 프로그래밍 정도를 낮춰야 한다.

## 추가 Q&A: 디스크·페이지·프레임
- **질문**: 디스크에서 프레임을 가져온다고 해도 되는가? 디스크의 정보는 실제로 페이지나 프레임인가?
- **정리**: 프레임은 RAM의 물리 공간 단위이고 페이지는 가상 주소 공간의 논리 단위다. 디스크에는 파일 블록이나 swap slot 형태의 바이트 데이터가 저장된다. “가상 페이지의 backing data를 디스크에서 읽어 물리 프레임에 적재한다”가 가장 엄밀한 표현이다.

## 모범답안 요점

가상 메모리는 프로세스별 가상 주소를 물리 메모리에 매핑하는 추상화다. 가상 주소는 VPN과 offset으로 나뉘며 MMU가 TLB와 페이지 테이블을 이용해 PFN을 찾고 offset을 그대로 결합한다. PTE에는 PFN, present, 권한, accessed, dirty 등이 들어간다.

페이지 폴트는 CPU가 주소 변환 중 발생시키는 동기 예외다. 커널은 유효한 접근인지 검사하고 backing data를 프레임에 적재한다. 필요하면 희생 페이지를 교체하고 dirty page를 write-back하며 PTE·TLB를 갱신한 후 명령을 재실행한다.

FIFO는 Belady’s Anomaly가 발생할 수 있고 LRU는 stack property로 발생하지 않는다. Clock은 reference bit가 1이면 0으로 지우고 넘기며 0이면 교체하는 LRU 근사다. 스래싱은 Working Set 합이 가용 프레임보다 커져 실행보다 폴트 처리에 시간을 쓰는 현상이며, 프레임 조정과 다중 프로그래밍 정도 축소로 완화한다.

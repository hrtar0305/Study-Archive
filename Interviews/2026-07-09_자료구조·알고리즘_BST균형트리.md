## 개념: BST / 균형 트리 / B-tree

### Q1~Q3. BST 정의·복잡도·편향
- **내 답변 요약**: 왼쪽 < 부모 < 오른쪽 규칙을 재귀적으로 만족하는 이진 트리. 탐색 O(H), 일반적으로 log N이나 skewed tree면 O(N). 정렬된(단조 증가/감소) 값을 순차 삽입하면 편향 발생.
- **평가**: 정확. **보완** — 엄밀한 BST 정의는 보통 중복 없는 왼<부모<오른쪽(중복 처리는 구현마다 다름).

### Q4~Q6. 균형 BST (AVL vs Red-Black)
- **내 답변 요약**: Red-Black(색칠 규칙으로 높이 조절)·AVL(모든 노드 좌우 높이차 ≤ 1, 회전으로 유지). AVL이 더 엄격 → 탐색 유리, 삽입·삭제 오버헤드 큼. 힌트 후 "AVL은 회전 상한이 없고 RB는 있다"로 정리.
- **평가**: 방향 정확. 회전 횟수 정량 차이는 힌트 필요.
- **모범답안**: AVL은 더 낮은 높이(≈1.44 log N)로 탐색이 미세하게 빠르고, 삽입/삭제 시 회전이 루트까지 전파될 수 있음. Red-Black은 높이 ≤ 2 log N으로 느슨한 대신 **삽입 ≤ 2회, 삭제 ≤ 3회 회전**이라는 상수 상한이 있어 갱신이 저렴. → 탐색(읽기) 위주 AVL, 삽입·삭제(쓰기) 잦음 Red-Black. 범용 라이브러리(Java TreeMap, C++ std::map, 리눅스 커널)는 읽기·쓰기 균형을 위해 대부분 Red-Black.

### Q7~Q8. B-tree / B+-tree (디스크)
- **내 답변 요약**: 다진(multi-way) 트리로 높이를 낮춰 디스크 I/O 횟수 감소. 노드 내부는 정렬된 키를 메모리에서 이진 탐색. 힌트 후 "디스크는 블록 단위로 읽으므로 한 번의 I/O로 많은 키를 가져오는 게 이득"까지 정확히 도달.
- **평가**: 핵심 도달. **보완** — 분기 B가 수백~수천이면 높이 log_B N이라 수백만 건도 3~4단계(디스크 접근 3~4번)로 끝남.
- **이월**: B+-tree의 리프 연결 리스트·range query·클러스터드 인덱스 등 상세는 사용자 요청으로 **DB 파트**에서 별도로 깊게 다룰 예정.

### 약점·복습포인트 (BST / 균형 트리)
- AVL vs RB의 회전 횟수 정량 차이(RB 상수 상한 vs AVL 전파 가능) 즉시 상기
- BST 탐색 O(log N)은 균형 전제 — 깨지면(skewed) O(N)
- B-tree가 빠른 근본 이유 = 블록 단위 I/O에 노드 크기를 맞춘다는 점

## Q1. BGP의 정의와 목적

- **질문**: BGP란 무엇이며 인터넷에서 어떤 문제를 해결하기 위해 사용되는 프로토콜인가?
- **내 답변 요약**: BGP를 처음 들어봤다고 답하고 힌트를 요청했다. 인터넷이 독립된 네트워크들의 연결이며 각 네트워크가 도달 가능한 IP 대역을 알려야 한다는 힌트 후에도 개념을 전혀 접해보지 않아 전체 설명을 요청했다.
- **평가**: BGP와 AS에 대한 사전 지식이 없어 L1 정의 질문에서 막혔다. 프로토콜에 따라 힌트 1회 후 정식 면접을 마무리하고, 예정했던 꼬리질문 범위까지 학습 모드로 전환했다.
- **모범답안**: BGP는 서로 다른 AS 사이에서 IP prefix의 도달 가능성과 경로 속성을 교환하고 운영 정책에 따라 사용할 경로를 선택하는 경로 벡터 프로토콜이다. 인터넷이 하나의 관리 주체가 아닌 다수의 독립 네트워크로 구성되기 때문에 AS 사이의 경로 교환에 사용된다.

## 후속 학습

### AS와 ASN

인터넷은 ISP, 클라우드 사업자, 대학, 기업처럼 서로 독립적으로 운영되는 네트워크들의 연결이다. 하나의 관리 주체와 공통 라우팅 정책 아래 운영되는 네트워크 집합을 AS(Autonomous System)라고 하며, 각 AS를 식별하는 번호를 ASN이라고 한다.

```text
AS 65001 ─ AS 65002 ─ AS 65003
                       203.0.113.0/24
```

AS 내부에서는 OSPF·IS-IS 같은 IGP를 사용할 수 있다. 서로 다른 AS가 어떤 IP prefix에 도달할 수 있는지 교환할 때 BGP를 사용한다.

### BGP의 역할

BGP(Border Gateway Protocol)는 AS 사이에서 IP prefix의 도달 가능성과 경로 속성을 교환하고 정책에 따라 경로를 선택하는 경로 벡터 프로토콜이다.

```text
AS 65003:
203.0.113.0/24는 나를 통해 도달 가능

AS 65001이 학습:
203.0.113.0/24 → AS 65002 → AS 65003
```

BGP 자체가 패킷을 전달하는 것은 아니다. BGP가 경로를 학습·선택해 RIB와 FIB에 반영하면 데이터 평면이 실제 패킷을 포워딩한다.

### BGP는 최단경로만 선택하지 않는다

OSPF는 일반적으로 링크 cost를 이용해 AS 내부의 최단 경로를 계산한다. BGP는 AS 사이의 사업 관계, 비용, 보안, 트래픽 정책을 중요하게 본다.

- customer·provider·peer 관계
- 특정 회선이나 출구 선호
- 특정 AS나 지역 회피
- 트래픽 엔지니어링 정책

LOCAL_PREF 같은 정책 속성이 우선할 수 있으므로 AS_PATH가 더 짧은 경로를 항상 선택하지는 않는다.

### eBGP와 iBGP

- eBGP: 서로 다른 AS 사이에서 경로 교환
- iBGP: 같은 AS 내부에서 외부로부터 학습한 BGP 경로 공유

```text
AS 65001 경계 라우터 ← eBGP → AS 65002 경계 라우터

AS 65001 내부:
경계 라우터 A ← iBGP → 경계 라우터 B
```

### BGP 세션과 메시지

BGP 피어는 일반적으로 상대 주소를 명시적으로 설정하고 TCP 179번 포트로 세션을 맺는다.

- OPEN: 세션 시작과 ASN 등 정보 교환
- KEEPALIVE: 세션 생존 확인
- UPDATE: 새로운 경로 광고 또는 기존 경로 철회
- NOTIFICATION: 오류 통지와 세션 종료

BGP는 신뢰성·순서·재전송을 TCP에 맡기고 경로 정보와 정책 처리에 집중한다.

### BGP 경로 정보와 속성

#### NLRI

광고하는 목적지 IP prefix다.

```text
203.0.113.0/24
```

#### AS_PATH

경로가 거쳐 온 AS 목록이다. 경로 선택과 AS 수준의 루프 방지에 사용된다.

```text
AS_PATH: 65002 65003
```

#### NEXT_HOP

해당 prefix로 가기 위해 다음으로 전달할 라우터 주소다.

#### LOCAL_PREF

자신의 AS에서 외부로 나갈 출구의 선호도를 표현한다. 일반적으로 높은 값을 선호하며 같은 AS 내부에서 공유한다.

#### MED

인접 AS가 자신의 AS로 들어올 때 어느 진입점을 선호하면 좋을지 제안한다. 일반적으로 낮은 값을 선호하지만 상대 AS가 정책상 무시할 수 있다.

#### COMMUNITY

경로에 정책용 태그를 붙여 광고 범위나 처리 정책을 제어할 수 있게 한다.

### BGP 경로 선택

같은 prefix에 대한 후보 경로가 여러 개라면 경로 속성과 정책으로 최적 경로를 선택한다. 세부 순서는 구현마다 다를 수 있지만 대표적으로 다음 요소를 본다.

1. 높은 LOCAL_PREF
2. 로컬에서 생성한 경로
3. 짧은 AS_PATH
4. 낮은 MED
5. eBGP·iBGP 경로 비교
6. NEXT_HOP까지의 내부 IGP 비용
7. 추가 tie-break 조건

BGP 경로 선택과 Longest Prefix Match는 다른 단계다.

- BGP 경로 선택: 같은 prefix에 대한 여러 후보 중 어떤 경로를 설치할지 결정
- Longest Prefix Match: 패킷과 일치하는 여러 FIB prefix 중 가장 구체적인 항목 선택

### AS_PATH와 루프 방지

경로가 AS를 통과할 때 AS_PATH에 ASN이 누적된다.

```text
AS 65003에서 시작: 65003
AS 65002를 거침:   65002 65003
AS 65001을 거침:   65001 65002 65003
```

라우터가 자신의 ASN이 포함된 AS_PATH를 받으면 이미 자신을 거친 경로이므로 거부한다. 이 방식으로 AS 수준의 라우팅 루프를 방지한다.

### 장애·경로 철회와 수렴

prefix에 더 이상 도달할 수 없으면 BGP UPDATE의 withdraw로 기존 경로를 철회한다.

```text
경로 철회
→ 이웃 AS가 경로 제거
→ 남은 후보 중 최적 경로 재선택
→ RIB·FIB 갱신
→ 다른 BGP 이웃에게 변경 전파
```

BGP 세션 장애는 TCP 연결 종료, KEEPALIVE 미수신에 따른 Hold Timer 만료, 선택적인 BFD 등으로 감지할 수 있다. 인터넷 규모와 정책 때문에 수렴이 느릴 수 있으며 경로가 반복적으로 선택·철회되는 path exploration이 발생할 수 있다.

### BGP와 OSPF의 연계

BGP는 외부 목적지 prefix와 AS 경로를 선택하고, OSPF 같은 IGP는 AS 내부에서 BGP NEXT_HOP까지 도달하는 경로를 계산한다.

```text
BGP: 목적지 prefix → BGP NEXT_HOP
OSPF: BGP NEXT_HOP → 내부 경로
FIB: 실제 전달 가능한 다음 홉·출력 인터페이스
```

BGP NEXT_HOP이 재귀적으로 내부 라우팅 정보에 의해 해석되어야 실제 FIB에 설치될 수 있다.

### iBGP 확장성과 Route Reflector

기본적으로 iBGP로 학습한 경로를 다른 iBGP 이웃에게 그대로 재광고하지 않으므로 모든 iBGP 라우터가 서로 세션을 맺는 full mesh가 필요할 수 있다.

라우터가 n개라면 세션 수는 `n(n-1)/2`가 되어 확장성이 떨어진다. Route Reflector를 사용하면 여러 라우터가 Reflector와 세션을 맺고 Reflector가 경로를 반사해 전달하도록 구성할 수 있다.

### BGP 보안

- Prefix hijacking: 소유하지 않은 prefix를 실수 또는 악의적으로 광고
- Route leak: 한 관계에서 받은 경로를 정책상 잘못된 다른 관계로 광고

대표적인 완화 방법:

- prefix·AS_PATH 필터링
- maximum-prefix 제한
- IRR 기반 필터
- RPKI·ROA를 이용한 출발지 AS 검증
- 사업 관계에 맞는 엄격한 export 정책

RPKI는 해당 prefix를 특정 AS가 광고하도록 허가했는지 검증하는 데 도움을 주지만 전체 AS_PATH의 진실성까지 완전히 보장하지는 않는다.

## 예상 꼬리질문과 모범답안

### OSPF와 BGP의 차이는 무엇인가

OSPF는 주로 하나의 AS 내부에서 링크 상태와 cost를 이용해 최단 경로를 계산하는 IGP다. BGP는 AS 사이에서 AS_PATH 등의 속성과 운영 정책을 이용해 경로를 선택한다.

### BGP는 가장 짧은 AS_PATH를 항상 선택하는가

아니다. LOCAL_PREF 같은 상위 정책이 우선할 수 있어 더 긴 AS_PATH가 선택될 수 있다.

### BGP가 TCP를 사용하는 이유는 무엇인가

UPDATE 메시지의 신뢰성·순서·재전송을 TCP에 맡기고 BGP는 경로와 정책 처리에 집중하기 위해서다.

### BGP의 루프 방지 방법은 무엇인가

AS_PATH에 자신의 ASN이 들어 있는 경로를 거부해 AS 수준의 루프를 방지한다.

### BGP 경로를 선택한 뒤 패킷은 어떻게 전달되는가

선택된 경로가 RIB와 FIB에 반영되고 데이터 평면이 패킷마다 Longest Prefix Match로 FIB를 조회해 포워딩한다.

### 대표적인 BGP 보안 한계는 무엇인가

잘못된 prefix 광고를 기본 BGP만으로 충분히 검증하지 못해 prefix hijacking과 route leak이 발생할 수 있다. 라우팅 필터와 RPKI 등으로 완화한다.

## 핵심 정리

BGP는 서로 다른 AS 사이에서 IP prefix 도달 가능성과 경로 속성을 교환하고 정책에 따라 경로를 선택하는 경로 벡터 프로토콜이다. eBGP는 AS 사이, iBGP는 같은 AS 내부에서 BGP 경로를 교환한다.

BGP는 TCP 179번을 사용하며 OPEN·KEEPALIVE·UPDATE·NOTIFICATION 메시지를 사용한다. LOCAL_PREF·AS_PATH·MED·NEXT_HOP·COMMUNITY 같은 속성을 경로 선택과 정책에 활용한다.

AS_PATH는 경로 선택과 AS 수준의 루프 방지에 사용된다. 선택된 경로는 RIB와 FIB에 반영되고 실제 패킷은 데이터 평면이 포워딩한다.

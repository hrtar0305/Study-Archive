## Q1. CPU 스케줄링의 정의
- **내 답변 요약**: 한정된 CPU 자원을 모든 프로세스가 나눠 갖도록 프로세스별 CPU 할당 시간을 배분하는 것이라고 설명했다.
- **평가**: 핵심은 정확했다. 실제 스케줄링 대상은 커널 스레드일 수 있으며 CPU 효율·응답성·처리량·공정성 등의 목표를 함께 언급하면 더 완전하다.

## Q2. 평가 지표
- **내 답변 요약**: 대표 지표가 무엇인지 파악하지 못했고 CPU burst인지 질문했다. 힌트 후에도 지표 명칭은 떠올리지 못했다.
- **평가**: 주요 약점이다. CPU burst는 워크로드 특성이고 utilization·throughput·turnaround·waiting·response time은 스케줄링 결과의 평가 지표다.

## Q3. 선점형·비선점형과 타이머 인터럽트
- **내 답변 요약**: 선점형은 운영체제가 실행 중인 프로세스에서 CPU를 강제로 회수할 수 있으며 다시 실행할 수 있도록 문맥 저장이 필요하다고 답했다. 제어권 회수 인터럽트를 처음에는 소프트웨어 인터럽트로 추측했지만 힌트 후 타이머를 추론했다.
- **평가**: 선점과 문맥 저장은 정확했다. 운영체제가 설정한 프로그래머블 하드웨어 타이머의 인터럽트로 커널이 주기적으로 제어권을 되찾는다.

## Q4. FCFS
- **내 답변 요약**: 먼저 도착한 작업부터 처리하는 비선점 큐 방식이며 긴 작업 뒤에서 짧은 작업들이 밀리는 convoy effect를 설명했다.
- **평가**: 정확했다.

## Q5. SJF·SRTF와 CPU burst 예측
- **내 답변 요약**: SJF는 작업 시간이 짧은 순으로 실행해 평균 대기 시간을 이론적으로 최소화하지만 미래 작업 시간을 알기 어렵다고 설명했다. 두 작업 순서를 교환하는 논리로 최적성을 설명했고 과거 데이터 기반 estimated time을 언급했다. 지수 평균식은 알지 못했지만 힌트 후 α가 최근 실제 burst에 주는 가중치임을 추론했다.
- **평가**: 알고리즘과 교환 논증은 좋았다. `τₙ₊₁=αtₙ+(1−α)τₙ`은 복습이 필요하다.
- **SRTF**: 새 작업의 burst가 현재 작업의 남은 시간보다 짧으면 선점하며 starvation을 aging으로 완화한다고 정확히 설명했다.

## Q6. Round Robin
- **내 답변 요약**: 각 작업에 고정된 time slice를 순환 배분하며 공정성이 높다고 설명했다. 퀀텀이 크면 FCFS와 비슷해지고 너무 작으면 컨텍스트 스위칭 오버헤드가 커진다고 답했다.
- **평가**: 정확했다.

## Q7. MLFQ
- **내 답변 요약**: 큐마다 다른 스케줄링을 적용한다고 설명했다. I/O로 일찍 반납하면 우선순위를 높이고 퀀텀을 모두 쓰면 낮추는 feedback 원리를 추론했다. 기아는 aging으로 해결했으나 조기 반납 gaming 방지는 알지 못했고 힌트 후 누적 CPU 사용량 기준 강등을 추론했다.
- **평가**: 기본 구조와 feedback은 질문을 통해 회복했다. 주기적 priority boost와 누적 CPU allotment를 복습해야 한다.

## Q8. 정량 계산

모든 작업이 시각 0에 A→B→C 순서로 도착하고 burst가 A=8, B=4, C=2인 상황을 계산했다.

- **내 답변 요약**: FCFS=ABC, SJF=CBA, RR(q=2)=ABCABAA의 실행 순서를 모두 맞혔다. 지표 계산은 처음에 답하지 못했지만 힌트 후 평균 turnaround와 response time을 구했다. FCFS turnaround 합을 처음 32로 계산했으나 재질문 후 34로 수정했다.
- **평가**: 실행 순서와 지표 적용은 최종적으로 정확했다.

## 모범답안 요점

- `turnaround = completion - arrival`
- `waiting = ready queue에서 기다린 시간의 합`
- `response = first run - arrival`
- 선점형 스케줄링은 하드웨어 타이머 인터럽트로 제어권을 회수한다.
- SJF는 예상 burst 최솟값, SRTF는 남은 시간 최솟값을 선택한다.
- 지수 평균: `τₙ₊₁=αtₙ+(1−α)τₙ`
- RR은 quantum이 크면 FCFS에 가까워지고 작으면 context switch 오버헤드가 증가한다.
- MLFQ는 feedback, periodic priority boost, cumulative CPU allotment를 사용한다.

### 계산 결과
- FCFS: `0-A-8-B-12-C-14` / 평균 turnaround=`34/3` / 평균 response=`20/3`
- SJF: `0-C-2-B-6-A-14` / 평균 turnaround=`22/3` / 평균 response=`8/3`
- RR(q=2): `0-A-2-B-4-C-6-A-8-B-10-A-12-A-14` / 평균 turnaround=`10` / 평균 response=`2`

## 약점·복습포인트

- Turnaround·waiting·response time 정의와 계산
- 선점은 소프트웨어 인터럽트가 아니라 하드웨어 타이머 인터럽트로 시작
- 지수 평균 CPU burst 예측식
- MLFQ priority boost, 누적 CPU allotment와 gaming 방지
- 스케줄링 대상은 커널 스레드일 수 있음

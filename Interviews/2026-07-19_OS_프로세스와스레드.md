## 개념: 프로세스와 스레드

### Q1. 프로세스와 스레드의 정의·차이
- **내 답변 요약**: 프로세스는 프로그램 인스턴스의 단위이고, 스레드는 프로세스의 실행 흐름 단위라고 설명했다. 프로세스마다 독립된 가상 메모리 영역을 가지며 같은 프로세스의 스레드들은 힙 등을 공유한다고 답했다.
- **평가**: 핵심 구분은 정확했다. 프로세스를 자원 소유·보호 단위, 스레드를 CPU 실행·스케줄링 단위로 표현하면 더 정밀하다.

### Q2. 스레드의 공유 자원과 독립 자원
- **내 답변 요약**: 코드·데이터·힙을 공유하고 각자 스택을 가진다고 설명했다. 스택에는 반환 주소와 지역 변수가 있으며, 레지스터 값도 스레드별로 저장한다고 답했다.
- **평가**: 주요 항목은 정확했다. 열린 파일과 프로세스 자원도 공유하며, 프로그램 카운터·스택 포인터·TLS·스케줄링 상태도 스레드별로 독립적이다.

### Q3. 프로세스와 스레드의 컨텍스트 스위칭
- **내 답변 요약**: 프로세스 전환은 레지스터 상태 외에 페이지 테이블 문맥이 바뀌며, 스레드 전환은 주소 공간을 공유해 더 저렴하다고 설명했다. TLB와 캐시 미스 영향도 언급했다.
- **평가**: 주소 공간 변경 비용을 잘 짚었다. CPU 캐시는 전환 시 반드시 flush되는 것이 아니라 새 작업 집합이 기존 내용을 밀어내며 간접적인 미스가 증가할 수 있다.

### Q4. TLB 엔트리의 주소 공간 구분
- **내 답변 요약**: 관련 명칭은 떠올리지 못했지만, 힌트 후 프로세스별 태그로 TLB 엔트리를 구분하여 유지할 수 있다고 추론했다.
- **평가**: 원리는 힌트 후 회복했다. 일반 명칭은 ASID이며 x86에서는 PCID라고 한다. 태그가 없다면 주소 공간 전환 때 관련 TLB 엔트리를 무효화해야 한다.

### Q5. 사용자 수준 스레드와 커널 수준 스레드
- **내 답변 요약**: 사용자 수준 스레드는 사용자 영역의 런타임이, 커널 수준 스레드는 커널이 스케줄링한다고 답했다. 블로킹 시스템 콜과 멀티코어 활용은 처음에 답하지 못했다. 힌트 후 커널이 내부 사용자 스레드를 개별 실행 단위로 보지 않는다면 하나의 블로킹이 전체 실행을 멈출 수 있다고 추론했다.
- **평가**: 스케줄러의 위치는 정확했다. 결론은 many-to-one 모델에서 성립하며, one-to-one과 M:N 모델에서는 커널이 여러 실행 단위를 스케줄링하므로 블로킹과 병렬성의 양상이 달라진다.

## 모범답안

프로세스는 실행 중인 프로그램의 인스턴스이자 독립된 가상 주소 공간과 운영체제 자원을 소유하는 보호 단위다. 스레드는 프로세스 안에서 명령을 수행하는 실행·스케줄링 단위다. 같은 프로세스의 스레드는 코드·데이터·힙·열린 파일을 공유하지만, 프로그램 카운터·레지스터·스택·TLS와 스케줄링 상태는 독립적으로 가진다.

프로세스와 스레드 전환 모두 실행 상태를 저장·복원하지만, 프로세스 전환은 주소 공간과 페이지 테이블 문맥까지 변경하므로 일반적으로 더 비싸다. ASID 또는 x86 PCID를 사용하면 서로 다른 주소 공간의 TLB 엔트리를 태그로 구분해 함께 유지할 수 있어 전체 TLB flush를 줄일 수 있다.

Many-to-one은 여러 사용자 스레드가 하나의 커널 스레드에 대응하므로 전환은 빠르지만, 블로킹 시스템 콜 하나가 전체를 막을 수 있고 동시에 하나의 코어만 사용할 수 있다. One-to-one은 사용자 스레드마다 커널 스레드가 대응해 블로킹 격리와 멀티코어 병렬 실행이 가능하지만 커널 관리 비용이 크다. M:N은 여러 사용자 스레드를 여러 커널 스레드에 다중화해 두 방식의 장점을 결합하지만 런타임 구현이 복잡하다.

## 추가 Q&A

- **질문**: 프로세스를 프로그램 인스턴스라고 표현해도 되는가?
- **답변**: 틀린 표현은 아니지만 “실행 중인 프로그램의 인스턴스”라고 해야 정적 프로그램과 구분된다. 면접에서는 독립된 주소 공간과 자원을 할당받는 자원 소유·보호 단위라는 설명을 함께 붙이는 것이 정확하다.

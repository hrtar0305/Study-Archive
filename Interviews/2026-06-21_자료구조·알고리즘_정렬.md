## 개념: 정렬 (Sorting)

### Q1. 대표 정렬 알고리즘과 복잡도
- **내 답변 요약**: insertion/selection/bubble/merge/heap/quick 나열. 대부분 복잡도 정확.
- **평가**: 윤곽 우수. **오류 2개**: insertion 최선 O(1)→**O(N)**(이미 정렬돼도 N-1회 비교), quick 최선 O(N)→**O(N log N)**(항상 균등 분할이 최선).
- **모범답안**:
  | 알고리즘 | 최선 | 평균 | 최악 | 공간 | 안정 |
  |---|---|---|---|---|---|
  | Insertion | O(N) | O(N²) | O(N²) | O(1) | ✓ |
  | Selection | O(N²) | O(N²) | O(N²) | O(1) | ✗ |
  | Bubble | O(N) | O(N²) | O(N²) | O(1) | ✓ |
  | Merge | O(N log N) | O(N log N) | O(N log N) | O(N) | ✓ |
  | Heap | O(N log N) | O(N log N) | O(N log N) | O(1) | ✗ |
  | Quick | O(N log N) | O(N log N) | O(N²) | O(log N) | ✗ |

### Q2~Q3. Quick sort 최악 발생 조건
- **내 답변 요약**: pivot 선택에 좌우. pivot이 양 끝단에 위치하면 O(N²). first-element pivot일 때 이미 정렬된 입력에서 pivot이 항상 최솟값→끝단.
- **평가**: 정확. 역정렬 입력도 동일.
- **모범답안**: pivot이 항상 최솟값/최댓값 → 한쪽이 비고 다른 쪽으로만 편중. first-element pivot + 정렬/역정렬 입력이 대표 케이스.

### Q4~Q5. worst-case O(N log N) 보장
- **내 답변 요약**: median-of-three 제시, 보장은 못 한다고 정확히 인지. 실제 보장 기법은 미지.
- **평가**: median-of-three가 보장 못 함을 안 것은 좋음.
- **모범답안**:
  - **Introsort**: quicksort 진행 중 재귀 깊이가 `2·⌊log N⌋` 초과 시 **heap sort로 전환** → worst-case O(N log N) 보장. C++ `std::sort`가 이 방식.
  - **Median-of-medians (BFPRT)**: 5개씩 그룹화해 중앙값을 재귀로 구해 O(N)에 정확한 중앙값 pivot. 이론적 보장이나 상수 커서 비실용.
  - 소규모 부분배열 insertion sort 전환은 상수 최적화일 뿐 보장과 별개.

### Q6. Ω(N log N) 하한 (결정 트리 논증)
- **내 답변 요약**: 비교로 pool 2등분→log N 깊이 필요. 정성적 방향만.
- **평가**: 방향 맞음. **정량화 미흡**.
- **모범답안**: N개 정렬 = N!가지 순열 중 하나 확정. 비교 1회 = 2가지 결과(≤/>) → 결정 트리는 이진 트리, 잎 ≥ N!개 필요. 트리 높이 ≥ log₂(N!). Stirling 근사로 **log₂(N!) = Θ(N log N)**.

### Q7~Q8. 비교 기반 한계 · Counting sort
- **내 답변 요약**: counting sort = 값을 bucket에 직접. 시간 O(N+K), 공간 O(K). domain 크면 비효율.
- **평가**: 정확.

### Q9. Radix sort
- **평가**: **미지(약점)**.
- **모범답안**: 가장 낮은 자릿수부터 자릿수 단위로 counting sort를 d회 반복. 복잡도 O(d(N+b)) (b=기수, d=자릿수). 각 자릿수 정렬이 반드시 **안정 정렬**이어야 함. 정수 범위 넓어도 d 작으면 사실상 선형.

### 체크포인트 추가 Q&A (사용자 질문)
1. **"비교 기반 정렬이 흔히 말하는 sort들인가?"** → insertion/selection/bubble/merge/heap/quick 모두 해당. 하한 정리 적용 대상. counting/radix/bucket은 비교 안 하므로 예외.
2. **"insertion 최선 O(N)은 하한과 다른가?"** → 하한 Ω(N log N)은 worst-case 보장. insertion O(N)은 이미 정렬된 특수 입력에서만(결정 트리의 짧은 경로). 층이 달라 모순 없음. insertion worst는 O(N²).
3. **"안정성은?"** → 같은 값의 상대 순서 유지. 안정=insertion/merge/bubble/counting, 불안정=selection/heap/quick. 다중 키 정렬·radix 정확성에 필수.

### 약점·복습포인트 (정렬)
- worst-case O(N log N) 보장 기법(Introsort 깊이 임계 + heap sort 전환, median-of-medians) 미지
- Ω(N log N) 하한의 정량 증명(N!→log₂(N!)=Θ(N log N) 결정 트리) 정립 필요
- Radix sort 동작·복잡도 미지
- 사소한 복잡도 오류: quick 최선 O(N log N), insertion 최선 O(N)

### 이해도: 🟡 보통
알고리즘 윤곽·quick 최악·counting sort는 탄탄. 하한 정량화, worst-case 보장 기법, radix sort가 보강 포인트.

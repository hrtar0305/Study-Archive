## Q1. OSI 7계층의 순서와 역할
- **내 답변 요약**: 물리, 데이터 링크, 인터넷, 전송, 세션, 표현, 응용 계층 순으로 나열했다. 물리 계층은 전기·광 신호, 데이터 링크 계층은 MAC과 스위치를 통한 LAN 전달, 3계층은 IP 라우팅, 전송 계층은 TCP·UDP, 응용 계층은 HTTP·SMTP 등이라고 설명했다. 세션·표현 계층의 역할은 기억하지 못했다.
- **평가**: 계층 순서는 사실상 정확했다. 다만 OSI 모델의 3계층 이름은 인터넷 계층이 아니라 **네트워크 계층**이다. 인터넷 계층은 TCP/IP 모델에서 사용하는 명칭이다. 전송 계층은 포트를 통한 프로세스 간 전달과 TCP의 신뢰성·흐름 제어 등을 담당한다.

## Q2. 세션 계층과 표현 계층
- **내 답변 요약**: OSI 모델은 이론적으로 세분화한 모델이고 현실의 TCP/IP 모델에서는 상위 세 계층을 응용 계층으로 묶기 때문에 세션·표현 계층의 구체적인 역할을 기억하지 못한다고 답했다.
- **평가**: TCP/IP 모델에서 OSI 5~7계층이 응용 계층으로 묶인다는 설명은 맞았다. 세션 계층은 대화·세션의 설정·유지·종료와 동기화·복구, 표현 계층은 데이터의 인코딩·직렬화·압축·암호화 등 표현 변환을 개념적으로 담당한다.

## Q3. TLS·JSON·세션 유지의 현실적 위치
- **내 답변 요약**: 세션 계층은 TCP로 established된 세션을 관리할 것이라고 추론하고, 표현 계층은 JSON 같은 데이터 형식 변환을 담당할 수 있다고 답했다. 현실의 TCP/IP 모델에서 TLS는 응용 계층 영역에 설계될 것이라고 설명했다.
- **평가**: JSON 직렬화와 TLS를 상위 계층 기능으로 본 방향은 대체로 맞았다. 다만 TCP 연결과 애플리케이션 세션은 동일하지 않다. TLS는 실무적으로 응용 프로토콜과 TCP 사이에서 동작하며 TCP/IP 모델에서는 넓게 응용 계층에 포함한다.

## Q4. 캡슐화 순서와 데이터 단위
- **내 답변 요약**: 애플리케이션 데이터에 TCP, IP, Ethernet 헤더 순으로 붙는다고 답했다. 처음에는 TCP 단계가 패킷, IP 단계가 세그먼트라고 반대로 말했다.
- **평가**: 헤더가 붙는 순서는 정확했다. 데이터 단위의 이름은 처음에 혼동했다.

## Q5. 힌트 이후 PDU와 역캡슐화
- **내 답변 요약**: 전송 계층은 세그먼트, 네트워크 계층은 패킷, 데이터 링크 계층은 프레임이라고 수정했다. 수신 측은 Ethernet, IP, TCP 헤더 순서로 제거한다고 설명했다.
- **평가**: 수정한 답변은 정확했다. 물리 계층에서는 비트와 물리 신호로 전달된다. UDP의 전송 계층 데이터 단위는 보통 UDP 데이터그램이라고 부른다.

## 핵심 정리

### OSI 7계층

| 계층 | 이름 | 핵심 역할 | 대표 예시 |
|---:|---|---|---|
| 7 | 응용 | 애플리케이션에 네트워크 서비스 제공 | HTTP, DNS, SMTP |
| 6 | 표현 | 인코딩·직렬화·압축·암호화 등 표현 변환 | JSON, UTF-8, 압축 |
| 5 | 세션 | 대화·세션의 설정·유지·종료, 동기화·복구 | 체크포인트, 대화 상태 |
| 4 | 전송 | 프로세스 간 전달, 포트, 신뢰성·흐름 제어 | TCP, UDP |
| 3 | 네트워크 | IP 주소와 라우팅을 통한 네트워크 간 전달 | IP, ICMP, 라우터 |
| 2 | 데이터 링크 | 같은 링크에서 MAC 기반 프레임 전달 | Ethernet, 스위치 |
| 1 | 물리 | 비트를 전기·광·무선 신호로 전송 | 케이블, 전파 |

### TCP/IP 모델과의 대응

```text
OSI 응용 + 표현 + 세션  → TCP/IP 응용 계층
OSI 전송               → TCP/IP 전송 계층
OSI 네트워크            → TCP/IP 인터넷 계층
OSI 데이터 링크 + 물리  → TCP/IP 링크 계층
```

OSI는 개념적 참조 모델이고 현실의 프로토콜이 각 계층에 항상 깔끔하게 하나씩 대응하지는 않는다. TCP/IP 모델을 5계층으로 설명할 때는 링크 계층에서 물리 계층을 별도로 나누기도 한다.

### TCP 연결과 애플리케이션 세션

- **TCP 연결**: IP와 포트의 조합으로 식별되는 전송 계층 연결
- **애플리케이션 세션**: 로그인 상태나 사용자 대화 상태처럼 애플리케이션이 관리하는 논리적 상태

TCP 연결이 끊겨도 쿠키나 토큰을 이용해 로그인 세션은 유지될 수 있다. 하나의 로그인 세션이 여러 TCP 연결을 사용할 수도 있다.

### 캡슐화와 PDU

```text
애플리케이션 데이터
→ TCP 헤더 + 데이터                 = TCP 세그먼트
→ IP 헤더 + TCP 세그먼트            = IP 패킷·데이터그램
→ Ethernet 헤더·트레일러 + IP 패킷  = Ethernet 프레임
→ 비트와 물리 신호
```

송신 측은 위에서 아래로 TCP, IP, Ethernet 정보를 붙인다. 수신 측은 아래에서 위로 Ethernet, IP, TCP 정보를 검사하고 제거한다.

```text
전송 계층: 세그먼트(TCP)·데이터그램(UDP)
네트워크 계층: 패킷·IP 데이터그램
데이터 링크 계층: 프레임
물리 계층: 비트
```

## 음성 답변의 사고 흐름·구성 평가

### 잘한 점
- 1계층부터 7계층까지 아래에서 위로 순서 있게 답해 구조가 명확했다.
- 기억나지 않는 세션·표현 계층을 억지로 단정하지 않고 TCP/IP 모델과 비교했다.
- 캡슐화 헤더 순서는 정확히 기억했고, PDU 명칭은 힌트 후 즉시 수정했다.

### 개선할 점
- OSI와 TCP/IP의 명칭이 섞여 네트워크 계층을 인터넷 계층이라고 불렀다.
- 세션 계층을 TCP 연결 관리와 바로 동일시했다. 전송 계층 연결과 애플리케이션의 논리적 세션을 분리해야 한다.
- 답변 시작 시 “OSI 모델 기준” 또는 “TCP/IP 모델 기준”이라고 기준을 선언하면 용어 혼동을 줄일 수 있다.
- 명백한 받아쓰기 오류는 지식 오류로 평가하지 않았으며 속도·억양·발음은 평가 대상이 아니다.

## 모범답안 요점

OSI 7계층은 물리, 데이터 링크, 네트워크, 전송, 세션, 표현, 응용 순이다. TCP/IP 모델에서는 OSI의 응용·표현·세션을 응용 계층으로, 네트워크 계층을 인터넷 계층으로, 데이터 링크·물리를 링크 계층으로 묶어 설명한다.

송신 측 캡슐화에서는 애플리케이션 데이터에 TCP, IP, Ethernet 정보가 차례로 붙어 세그먼트, 패킷, 프레임이 된다. 수신 측은 반대 순서로 역캡슐화한다. TCP 연결과 로그인 같은 애플리케이션 세션은 서로 다른 개념이다.

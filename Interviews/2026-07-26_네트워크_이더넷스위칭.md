## Q1. 스위치와 라우터의 차이
- **내 답변 요약**: 스위치는 L2 장비이고 라우터는 L3 장비이며 두 장비의 목적이 다르다고 설명했다.
- **평가**: 계층 구분은 맞았다. 다만 “L2 레이어 간 연결”이라는 표현만으로는 실제 전달 기준과 범위를 설명하지 못한다.

## Q2. 전달에 사용하는 주소와 범위
- **내 답변 요약**: 스위치는 MAC 주소, 라우터는 IP 주소로 목적지를 정한다고 답했다. 스위치는 같은 LAN에서 프레임을 전달하고 라우터의 범위에는 특별한 한계가 없다고 설명했다.
- **평가**: 스위치와 라우터가 사용하는 주소 및 스위치의 일반적인 범위는 정확했다. 라우터는 무제한으로 전달하는 장비가 아니라 라우팅 테이블을 통해 도달 가능한 서로 다른 IP 네트워크 사이에서 패킷을 전달한다.

## Q3. MAC 주소 테이블 학습
- **내 답변 요약**: 원하는 IP·MAC 매핑이 없으면 브로드캐스트로 해당 IP의 호스트에게 MAC을 요청하고 결과를 MAC 주소 테이블에 저장한다고 설명했다.
- **평가**: 호스트의 ARP 동작과 스위치의 MAC 주소 학습을 혼동했다. 스위치는 IP 주소의 주인을 직접 찾지 않는다. 수신한 프레임의 출발지 MAC 주소와 프레임이 들어온 물리 포트를 보고 학습한다.

## Q4. ARP 캐시와 MAC 주소 테이블
- **내 답변 요약**: 호스트의 ARP 캐시는 IP 주소와 MAC 주소를 매핑한다고 답했다. 스위치의 MAC 주소 테이블은 정확히 설명하지 못했다.
- **평가**: ARP 캐시의 역할은 정확했다. 스위치의 MAC 주소 테이블은 MAC 주소와 스위치 포트를 매핑한다.

## Q5. 힌트 이후 MAC 학습과 unknown unicast
- **내 답변 요약**: 출발지 MAC 주소와 들어온 물리 포트 번호를 기반으로 엔트리를 만든다고 추론했다. 목적지 MAC이 테이블에 없으면 브로드캐스팅할 것이라고 생각했다.
- **평가**: `MAC 주소 → 물리 포트` 학습은 도출했다. 목적지 위치를 모르는 유니캐스트 프레임은 목적지 주소를 브로드캐스트로 바꾸는 것이 아니라 원래 목적지 MAC을 유지한 채 수신 포트를 제외한 같은 VLAN의 포트들로 플러딩한다.

## 후속 질문: 플러딩과 전달의 차이

플러딩도 넓은 의미에서는 프레임 전달 방식이다. 일반적인 알려진 유니캐스트 포워딩은 목적지 MAC에 대응하는 포트 하나로만 내보내지만, 플러딩은 수신 포트를 제외한 동일 VLAN의 여러 포트로 프레임을 복제해 내보낸다.

```text
알려진 유니캐스트:
포트 1로 수신 → MAC 테이블 조회 → 포트 3으로만 전달

Unknown unicast flooding:
포트 1로 수신 → 목적지 MAC 위치 없음 → 포트 2·3·4로 복제
```

Unknown unicast flooding에서도 프레임의 목적지 MAC은 원래 유니캐스트 주소로 유지된다. 목적지 호스트만 프레임을 처리하고 다른 호스트는 자신의 MAC 주소가 아니므로 버린다.

브로드캐스트는 주소의 종류이고 플러딩은 스위치가 여러 포트로 내보내는 동작이다. 브로드캐스트 프레임도 스위치에서 플러딩되지만 모든 플러딩 프레임이 브로드캐스트인 것은 아니다.

## 핵심 정리

### 스위치와 라우터

- **스위치**: 이더넷 프레임의 목적지 MAC 주소를 보고 같은 LAN 또는 VLAN 안에서 전달하는 L2 장비
- **라우터**: IP 패킷의 목적지 IP 주소와 라우팅 테이블을 보고 서로 다른 IP 네트워크 사이에서 전달하는 L3 장비

### MAC 주소 테이블 학습

스위치는 프레임이 들어올 때마다 출발지 MAC 주소와 수신 포트를 학습한다.

```text
포트 1에서 출발지 MAC AA:AA:AA:AA:AA:AA 프레임 수신
→ AA:AA:AA:AA:AA:AA → 포트 1 저장
```

엔트리는 영구적이지 않으며 일정 시간 사용되지 않으면 aging으로 제거된다. 호스트가 다른 포트로 이동하면 새 프레임의 출발지 MAC을 통해 매핑이 갱신될 수 있다.

### 목적지 MAC에 따른 처리

- 목적지 MAC을 알고 있음: 해당 포트 하나로 전달
- 목적지 MAC의 포트가 수신 포트와 같음: 다른 포트로 전달하지 않음
- 목적지 MAC을 모름: 수신 포트를 제외한 같은 VLAN의 모든 포트로 unknown unicast flooding
- 브로드캐스트 MAC: 수신 포트를 제외한 같은 VLAN의 모든 포트로 flooding

### ARP와 스위치 학습

```text
호스트 ARP 캐시: 다음 홉 IP → 다음 홉 MAC
스위치 MAC 테이블: MAC → 스위치 포트
라우터 라우팅 테이블: 목적지 IP prefix → 다음 홉·출력 인터페이스
```

호스트는 다음 홉의 MAC을 모르면 ARP Request를 이더넷 브로드캐스트로 보낸다. 스위치는 이를 같은 VLAN에 플러딩한다. 해당 IP의 호스트가 ARP Reply를 보내면 요청 호스트가 ARP 캐시에 IP·MAC 매핑을 저장한다.

이와 별개로 스위치는 지나가는 ARP Request와 Reply도 일반 이더넷 프레임처럼 처리하며 각 프레임의 출발지 MAC과 수신 포트를 자신의 MAC 주소 테이블에 학습한다.

### 충돌 도메인과 브로드캐스트 도메인

스위치의 각 포트는 충돌 도메인을 분리한다. 같은 VLAN의 포트들은 하나의 브로드캐스트 도메인에 속한다. 라우터 또는 VLAN 간 라우팅은 브로드캐스트 도메인을 분리한다.

## 음성 답변의 사고 흐름·구성 평가

### 잘한 점
- 계층 구분에서 시작하여 MAC·IP 주소와 전달 범위로 구체화했다.
- ARP 캐시의 IP·MAC 매핑은 정확히 기억했다.
- 힌트 이후 출발지 MAC과 수신 포트의 매핑을 논리적으로 도출했다.

### 개선할 점
- MAC 주소 테이블 질문에서 익숙한 ARP 절차를 먼저 떠올리며 두 동작을 합쳐 설명했다.
- `호스트의 ARP`, `스위치의 MAC 학습`, `라우터의 라우팅`을 수행 주체와 테이블 기준으로 먼저 분리해야 한다.
- 불확실할 때 추론한 결론을 완전한 문장으로 먼저 말하고 이후 불확실성을 덧붙이는 편이 전달력이 좋다.
- 명백한 받아쓰기 오류는 지식 오류로 평가하지 않았으며 속도·억양·발음은 평가 대상이 아니다.

## 모범답안 요점

스위치는 목적지 MAC 주소와 MAC 주소 테이블을 이용해 같은 LAN·VLAN에서 이더넷 프레임을 전달한다. MAC 주소 테이블은 수신 프레임의 출발지 MAC과 수신 포트를 보고 `MAC → 포트` 형태로 학습한다.

목적지 MAC을 알고 있으면 해당 포트로만 포워딩하고, 모르면 수신 포트를 제외한 같은 VLAN 전체로 unknown unicast flooding한다. 이때 목적지 MAC 주소를 브로드캐스트로 변경하지 않는다.

호스트의 ARP 캐시는 `IP → MAC`, 스위치의 MAC 주소 테이블은 `MAC → 포트`, 라우터의 라우팅 테이블은 `목적지 IP prefix → 다음 홉·출력 인터페이스`를 저장한다.

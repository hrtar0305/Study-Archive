## 개념: 연결 리스트

### Q1. 정의
- **내 답변 요약**: 노드와 다음 노드 포인터로 이루어진 동적 자료구조.
- **평가**: 기본 구조는 정확하며, 노드가 일반적으로 비연속 메모리에 배치된다는 점을 보강할 필요가 있음.

### Q2~Q3. 시간복잡도
- **내 답변 요약**: 탐색 O(N), 포인터 재연결 자체는 O(1), 위치 탐색을 포함한 중간 삽입·삭제는 O(N).
- **평가**: 처음에는 배열과 연결 리스트의 random access 방향을 반대로 답변. 정확히는 배열 인덱스 접근 O(1), 연결 리스트 임의 위치 접근 O(N).

### Q4. 캐시 효율
- **내 답변 요약**: 일반적인 연결 리스트는 노드가 비연속적으로 배치되어 spatial locality가 낮고 pointer chasing 때문에 배열보다 캐시 효율이 떨어짐.
- **평가**: 정확. 단, pool allocator 등으로 노드가 가깝게 배치되는 구현에서는 정도가 달라질 수 있음.

### Q5~Q6. 이중 연결 리스트
- **내 답변 요약**: prev 포인터를 추가해 양방향 탐색이 가능하고, 노드 포인터를 이미 알면 이전 노드를 다시 찾지 않고 O(1)에 분리 가능.
- **평가**: 정확.

### Q7~Q10. LRU 캐시 구현
- **내 답변 요약**: HashMap(key→node) + 이중 연결 리스트. hit 시 head로 이동하고, 용량 초과 시 tail을 제거.
- **평가**: 구조와 동작은 정확. LRU를 빈도 기반으로 표현한 점과 퇴거 시 HashMap에서도 제거해야 한다는 점이 약점.

### 약점·복습포인트
- 배열 O(1) random access ↔ 연결 리스트 O(N)
- LRU=최근성(recency), LFU=빈도(frequency)
- LRU 퇴거 시 HashMap에서도 함께 제거
